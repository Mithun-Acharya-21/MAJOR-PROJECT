# Dataset Notes — EmotiSense AI

## Text Datasets

### RSDD (Reddit Self-reported Depression Dataset)
- **Source**: Reddit posts from r/depression and r/SuicideWatch
- **Labels**: Self-reported depression (binary)
- **Size**: ~3,000 posts
- **Notes**: Real-world social media data; informal language, slang, emojis

### eRisk / CLEF
- **Source**: eRisk shared task at CLEF
- **Labels**: Depression risk (binary)
- **Size**: ~5,000+ documents
- **Notes**: Longitudinal data; some entries span weeks of posting history

### Twitter Depression Dataset (Kaggle)
- **Source**: Kaggle dataset of labeled tweets
- **Labels**: Depression / non-depression (binary)
- **Size**: ~20,000 tweets
- **Notes**: Short text; high noise; requires careful preprocessing

## Facial Expression Datasets

### FER-2013
- **Source**: Kaggle Facial Expression Recognition Challenge
- **Labels**: 7 emotions (angry, disgust, fear, happy, sad, surprise, neutral)
- **Size**: ~35,000 images (48×48 grayscale)
- **Notes**: Used as proxy for depression-related facial cues (sadness, flat affect)

### RAF-DB (Real-world Affective Faces Database)
- **Source**: Beijing Normal University
- **Labels**: 7 basic emotions + valence/arousal
- **Size**: ~30,000 images
- **Notes**: More diverse demographics and real-world conditions

### CK+ (Extended Cohn-Kanade Dataset)
- **Source**: Carnegie Mellon University
- **Labels**: 7 expressions + AU codes
- **Size**: ~600 sequences, 327 labeled
- **Notes**: Lab-controlled; high quality; limited diversity

## Preprocessing Pipeline

1. **Text**: Unicode normalization → URL/mention removal → slang expansion → emoji → text → lowercase → whitespace cleanup
2. **Face**: OpenCV Haar cascade detection → center crop with padding → resize 224×224 → ImageNet normalization
3. **Labels**: Mapped to binary (0=non-depressed, 1=depressed) regardless of original encoding

## EATD verified inventory (Phase 1)

- 162 participant folders (83 `train/` + 79 `validation/`), 486 prompted sessions.
- Numeric folder ids are partition-local: 58 ids occur in both partitions but
  share no audio hashes and no transcripts, so they are distinct participants.
- Labels are **Zung SDS**: `label.txt` = raw total, `new_label.txt` = index
  (= raw × 1.25), binary label = `index >= 50`. This reproduces the legacy CSV
  for all 162 participants with zero mismatches.
- Text and audio are aligned per participant×topic; all 486 legacy CSV texts are
  identical to the raw transcripts.
- `_out.wav` is a processed variant of the same session, not an extra sample.
- Manifests, validation report and participant-level splits:
  `data/processed/eatd/` (generated by `scripts/build_eatd_manifest.py`).

## Limitations

- Datasets are proxy signals, not clinical diagnoses
- FER-2013 emotions ≠ depression; we use sadness/flat affect as indicators
- Class imbalance exists in most datasets
- Demographic representation varies across datasets

## CRITICAL: Cross-Modal Data Integrity Statement

**EATD (text) and FER-2013 (facial expression) are NOT aligned multimodal
depression samples.**

- EATD is a text/interview dataset with depression labels per subject.
- FER-2013 is a 7-class facial **expression** dataset (angry, disgust, fear,
  happy, sad, surprise, neutral) with NO subject-level correspondence to EATD
  and NO depression labels — expression ≠ depression.
- There is currently **no legitimate subject-level FACE/video dataset** in
  this repository that connects face and photo modalities to the other
  signals per participant.
- **Correction (Phase 1):** an aligned **text + voice** corpus DOES exist in
  `data/eatd/` — 162 participants, three prompted sessions each, with SDS
  scores. See `docs/eatd_dataset_card.md` and
  `data/processed/eatd/validation_report.json`. The earlier statement that no
  aligned multimodal data existed applied to face/video only.

Consequences enforced in this project:

1. No fake cross-modal labels are created; the modalities are never treated
   as aligned samples of the same subjects.
2. No joint multimodal accuracy is fabricated from misaligned datasets. The
   fusion model's reported metrics must come from a properly aligned
   held-out evaluation dataset; until one exists, metrics files remain
   explicitly marked `status: placeholder` and are surfaced as such.
3. Per-modality branches are evaluated only on their own modality's dataset.
4. The screening pipeline fuses modality *probabilities* at inference time —
   an architectural choice — and does not claim joint training or joint
   validation on aligned multimodal data.

Any future multimodal evaluation requires a dataset with true subject-level
alignment across modalities (e.g., EATD itself, which contains aligned
text/voice/video per subject, or DAIC-WOZ).
